Shopify Rundown

For you — since this is your first Shopify build, here's the fast version of everything worth being fluent on tonight.

Store setup

Domain: cj-custom-rods-vyc3hzbx.myshopify.com. The storefront password page can't be removed pre-transfer, so the raw Shopify URL will hit a password wall — normal.

How products get organized

Good to have crisp if Chris asks why there's no dedicated "Ice Rods" tab in Shopify admin:

  • 3 real Shopify Collections — In-Stock Rods, Reels, Apparel. These are the only structural buckets in admin.
  • Series and Ice/Open Water are tags, not collections — every rod carries a water-type tag and a series tag; the frontend queries by tag combination. Deliberate simplification after an earlier over-complicated pass — don't second-guess it.
  • Products must be individually published to your storefront channel — "Active" in Shopify doesn't make a product visible to your headless storefront automatically. Collections need their own separate publish toggle too. You've hit both bugs before and know the fix — first thing to check if something's missing tonight.

Metafields

Shopify's structured custom-data system (namespace + key, e.g. custom.rod_length) — this is the mechanism behind the whole product-page discussion above.

  • Off by default, per field — each metafield definition has its own Storefront API access toggle, no account-wide switch. A blank spec on a live page is almost always this.
  • Category metafields (Shopify's built-in taxonomy dropdowns) were rejected in favor of all-custom metafields — one system, Chris types free text instead of picking from Shopify's fixed vocabulary.
  • Unconfirmed: reel metafield toggles (Bearings, Gear Ratio, Weight, Max Drag) — values are filled in Shopify but the Storefront toggle hasn't been double-checked. If reel specs look empty tonight, check this first — 30-second fix, can even do it live.

Cart / checkout

Good to have crisp if Chris asks when it'll actually work:

  • Old Shopify Checkout API is dead (shut down April 2025) — you're correctly targeting the current Cart API. Confirms your plan is current, nothing to explain away.
  • Once wired: Add to Cart → builds a cart → redirects to Shopify's own hosted checkout.
  • You'll test pre-launch with Bogus Gateway, Shopify's fake payment processor. Standard cart checkout tests fine on your current store type.

Rod builder's future checkout mechanism

If it comes up: a builder with length + blank + color + thread + grip is 6+ option categories, and Shopify caps every product at 3 options max, regardless of variant count. (Common outdated assumption is a "100 variant" ceiling — that was raised to 2,048 in 2025, but the 3-option cap never moved.) So the plan is Admin API draft orders instead: price calculated server-side, a draft order created, customer pays through its invoiceUrl. Only fully testable once the store is transferred/on a paid plan.
