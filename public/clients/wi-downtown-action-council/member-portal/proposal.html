What You're Getting

Portal Landing

/member-portal
  • Public entry point — no login required, this is what a first-time visitor sees
  • Previews the three resource categories to sell the value before the login wall
  • Links back to WDAC's existing Membership page — nothing duplicated

Login

/member-portal/login
  • Org-level authentication, not a contact form — one login per member organization
  • Built to survive staff turnover — the login stays with the org, not the person
  • Gates everything past this point with session-based access

Dashboard

/member-portal/dashboard
  • The logged-in home base — pulls live counts and recent activity, nothing to update by hand
  • Category cards link straight into a pre-filtered library
  • "Add a Resource" link shows only for WDAC admin accounts — member orgs never see it

Resource Library

/member-portal/resources
  • A searchable, filterable content database, not a static page
  • Keyword search and category filter work together, live
  • Listing shape — flat rows or dedicated detail pages — is one of the open items below

Org Account

/member-portal/account
  • Where each organization manages its own credentials and membership state
  • Org name, contact email, and password — editable by the org itself
  • Membership status is set on WDAC's side, reflecting whatever the renewal process becomes

Add a Resource

/member-portal/resources/add
  • A real publishing workflow, not a form buried in an admin panel
  • Board members — and eventually part-time staff — publish title, category, PDF, and description themselves
  • Goes live in the library and on the Dashboard immediately — no developer touches it

Custom CMS

Built For What The Board Manages

Not a generic dashboard bolted onto a template — a content system built around resources, categories, and accounts.

  • Structured for what board members publish — resources, categories, and dates stay organized, not buried in a page builder
  • Publish a PDF and it's live on the Dashboard and in the Library immediately — no separate "go live" step
  • Org accounts, categories, and library content are managed directly by the board — no developer, no waiting
  • Owned outright by WDAC. No software license, no monthly CMS fee
Access Control

Built Around Who's Actually Logging In

This isn't a contact form with a password on it — it's a real permissions system with two distinct roles.

  • One login per member organization, not per individual — survives staff turnover by design
  • WDAC admin accounts see the publishing tools; member orgs never do — same system, two different experiences
  • Session-based authentication gates everything past the portal landing page
  • Membership status lives on WDAC's side, so it always matches WDAC's actual renewal process
Subdomain Architecture

The Main Site Doesn't Change

The portal is its own space, linked from WDAC's current site — not a rebuild of anything that already exists.

  • Lives on its own subdomain, so WDAC's existing WordPress site, plugins, and DNS stay exactly as they are
  • One new link added to the main site's nav — everything else there is untouched
  • No legacy roster to import — WDAC's last membership list turned over with conference registration, so the portal launches clean
  • Built to scale on its own as the library grows, without touching the main site's stack
03

Why This Portal Matters

Right now, anything WDAC wants to share with its member organizations — best practices, legislative updates, grant resources — has nowhere consistent to live. It goes out over email, or sits on a static page on your main site with no way to gate it to actual members. There's no record of what's already been shared, and no way for a member org to search it later. This portal fixes that: one place to point people, one login that survives staff turnover at every member organization, and a system simple enough that your board keeps it current without needing me in the loop for every new PDF.

— Jordan
